# השעות של אופיר

אפליקציית Web (PWA) פשוטה לדיווח שעות עבודה. נבנתה לפי העקרון: דיווח רגיל עם מקום עבודה שכבר מוגדר צריך לקחת כ-10-15 שניות.

## מצב נוכחי

**זהו MVP עובד במצב הדגמה (Local Storage).** אין עדיין חיבור לענן (Supabase) ואין חיבור ל-GHL. כל הנתונים נשמרים בדפדפן של המכשיר בלבד. זה בכוונה: קודם בודקים שה-UX נכון, אחר כך מחברים אינטגרציות.

## מה עובד

- מסך "דיווח": בחירת מקום עבודה (כולל 3 אחרונים כפתורי בחירה מהירה), קבוצה אופציונלית, תאריך, שעות, תעריף הניתן לשינוי לדיווח בודד, חישוב אוטומטי של משך וסכום, כפתור "כמו בפעם הקודמת".
- **טיימר (שעון נוכחות)**: כפתור "▶ התחל טיימר" עצמאי מתחת לטופס הרגיל. מודד זמן אמיתי מרגע ההתחלה (שורד רענון דף, לא ספירה בזיכרון), מציג טיוטה לבדיקה ואישור לפני שמירה, מעגל לדקה הקרובה (מתחת ל-30 שניות מתעגל לאפס ודורש עריכה ידנית לפני שמירה).
- מסך "החודש שלי": ניווט בין חודשים, 3 KPI (שעות, סכום עבודה, טרם חויב), סינון לפי מקום עבודה, סיכום לפי מקום עבודה, עריכה ומחיקה של דיווחים, ייצוא CSV (עם BOM לעברית ב-Excel, מוגן מ-formula injection), הכנה לחשבון עסקה (בחירת דיווחים מאותו מקום עבודה, מעבר לסטטוס "מוכן לחיוב" - ללא הפקת מסמך אמיתי).
- מסך "הגדרות": ניהול מקומות עבודה (שם, תעריף ברירת מחדל, סוג תעריף, תעריף שבת אופציונלי) וקבוצות, גיבוי וייבוא JSON.
- **קטלוג סוגי שיעורים גלובלי**: כל שם קבוצה/סוג שיעור שנוצר פעם אחת (למשל "פילאטיס", "מחול") זמין מיד כבחירה מרשימה לכל מקום עבודה אחר, כולל חדש - אין צורך להקליד מחדש.
- **תעריף שבת**: לכל מקום עבודה אפשר להגדיר תעריף מיוחד לשבת. כשתאריך הדיווח חל בשבת והתעריף עדיין לא נערך ידנית, הוא נטען אוטומטית במקום תעריף ברירת המחדל (עם הודעה קטנה שמסבירה שזה קרה).
- **ארכיון**: מקום עבודה לא פעיל ("לקוח עבר") עובר לאזור ארכיון מתקפל נפרד במקום להתערבב עם הרשימה הפעילה, עם אפשרות שחזור.
- שלושה סטטוסים לכל דיווח: דווח / מוכן לחיוב / חויב. דיווח שחויב נעול לעריכה ומחיקה.
- חישוב מדויק בדקות ואגורות (לא בעיגולי שעות עשרוניים), כולל תמיכה בתעריף שעתי ובתעריף קבוע לשיעור.
- עברית, RTL מלא, מותאם למובייל (נבדק ב-320px, 375px, 390px, 430px, ללא גלילה אופקית).
- PWA: manifest, אייקונים, service worker בסיסי לאפליקציית מעטפת (app shell). פרוס בפועל ב-Vercel (PWA מלא עובד שם; לא עובד בתוך Artifact בגלל חסימת Service Worker בסביבת ה-sandbox).

## מה לא נבנה בשלב הזה (בכוונה)

- אין טיימר (start/stop) - רק דיווח ידני. אפשר להוסיף בהמשך.
- אין Supabase/Auth - אין כניסה אישית, הנתונים מקומיים למכשיר בלבד.
- אין סנכרון בין מכשירים.
- אין חיבור אמיתי ל-GHL, ל-Morning או ל-Google Calendar. שכבת ה-Data מוכנה לכך (ראו למטה).
- אין בדיקות אוטומטיות (unit tests) - האימות שנעשה הוא בדיקות זרימה ידניות עם Playwright (ראו "מה נבדק בפועל").

## איך מריצים מקומית

```bash
npm install
npm run dev
```

האפליקציה עולה על `http://localhost:5173`. בפתיחה ראשונה נטענים נתוני הדגמה (שני מקומות עבודה, קבוצות ודיווחים לדוגמה) אוטומטית.

לבדיקת גרסת production:

```bash
npm run build
npm run preview
```

## היכן נמצאת שכבת הנתונים (Data Layer)

זו הנקודה החשובה לחיבור עתידי ל-GHL / Supabase:

- `src/repositories/localRepository.ts` - הקובץ היחיד שמדבר עם localStorage ישירות.
- `src/services/worklogService.ts` - ה-API הציבורי שכל המסכים משתמשים בו (`createWorkSession`, `updateWorkSession`, `deleteWorkSession`, `getWorkSessions`, `getWorkplaces`, `getGroups`, `prepareBillingBatch`, וכו'). **זהו הקובץ שצריך לגעת בו כדי להוסיף סנכרון ל-GHL** (למשל קריאת Webhook בסוף `createWorkSession` ו-`prepareBillingBatch`), או כדי להחליף את localRepository בגרסה שמתחברת ל-Supabase.
- `src/types/index.ts` - כל טיפוסי הנתונים (Workplace, Group, WorkSession, BillingBatch).

מבנה הקוד מפריד בין UI (`components/`, `screens/`) ללוגיקה עסקית (`services/`, `utils/`) ולגישה לנתונים (`repositories/`), כך שהחלפת האחסון לא דורשת לגעת במסכים.

## איך מתחברים לשירותי ענן בעתיד

1. Supabase: ליצור `src/repositories/supabaseRepository.ts` עם אותה חתימה (shape) כמו `localRepository.ts`, ולהחליף את הייבוא ב-`worklogService.ts`.
2. GHL: לפי המפרט שסוכם, יתווסף Webhook חד-כיווני מתוך `worklogService.ts` (אחרי `createWorkSession` ואחרי `prepareBillingBatch` בהצלחה) לכתובת Workflow Trigger ב-GHL. **לא בוצע עדיין בפועל, רק בתכנון** - כל פעולה מול GHL מחכה לאישור מפורש.

## מה נבדק בפועל

נבדק עם Playwright (דפדפן headless), לא על מכשיר iPhone/Android פיזי:

- שמירת דיווח חדש עם בחירה מהירה של מקום עבודה, חישוב משך וסכום נכון (17:00-19:00, 150 ₪/שעה → 2 שעות, 300 ₪).
- עריכת דיווח קיים ועדכון סכום בהתאם לתעריף חדש.
- מחיקת דיווח עם אישור.
- הכנת חיוב (Billing Batch) לדיווחים מאותו מקום עבודה, עדכון סטטוס ל"מוכן לחיוב".
- ייצוא CSV: BOM תקין, כותרות ונתונים בעברית.
- רוחבים 320px / 375px / 390px / 430px ללא גלילה אופקית ותוכן מוסתר.
- טעינת manifest, אייקונים ו-service worker.
- `npm run build` ו-`tsc -b --noEmit` עוברים ללא שגיאות.

**לא נבדק**: מכשיר פיזי אמיתי, PWA install flow בפועל באייפון/אנדרואיד, עבודה אמיתית ללא אינטרנט (כרגע האפליקציה כולה מקומית, אז "בלי אינטרנט" כבר עובד במובן הבסיסי, אבל אין עדיין מנגנון sync לבדוק).
